Local Git Quick Reference

A small cheat-sheet for initializing, committing, branching, and pushing.

  1. Go to the folder you want the repo in (use your terminal): 
    cd path/to/your/folder
  2. Initialize a repo: 
    git init
  3. To commit a change:
    1. Stage files: 
      git add .
      or 
      git add file.txt
    2. Create a commit: 
      git commit -m "Message text description"
  4. View commits: 
    git log
  5. Checkout commit or branch: 
    git checkout <commit-id-or-branch-name>

    To create and switch to a new branch:

    git checkout -b branch-name
  6. Connect to GitHub (add remote):

    If you use SSH keys:

    git remote add origin git@github.com:username/repo.git

    If you don't use SSH keys, follow the link below to set them up in a new tab:

    Set up SSH keys (opens new tab)

  7. Configure Git user & check config:

    Set your name and email for commits (local repo):

    git config user.name "CarelessCurve"
git config user.email "you@example.com"

    Set globally (applies to all repos on this machine):

    git config --global user.name "CarelessCurve"
git config --global user.email "you@example.com"

    Check configured values:

    git config user.name
git config user.email
git config --list

    Edit config file in your editor:

    git config --edit
git config --global --edit

    On Windows your global config typically lives at %USERPROFILE%\.gitconfig.

  8. Push to GitHub: 
    git push -u origin master
git push -u origin new-branch
  9. Create and merge pull requests:

    On GitHub open a Pull Request from your branch; repo owner can merge and resolve conflicts there.

  10. Pull changes from remote: 
    git pull origin master

Quick tips: replace master with your repo's default branch if different (e.g., main).

Advanced: Merge, Rebase & Squash

Git Merge

Combines two branches by creating a merge commit that ties the histories together. Preserves the full history of both branches.

Scenario:

Before merge:
master:  A - B - C
         /
feature:      D - E

After git merge feature (on master):
master:  A - B - C - M (merge commit)
         \         /
feature:      D - E

Use command:

git checkout master
git merge feature

When to use:

  • Merging stable feature branches back to Main
  • You want to keep all history and context
  • Working in a team (safer, explicit merge points)

Git Rebase

Re-applies your commits on top of another branch. Creates a linear history without merge commits.

Scenario:

Before rebase:
master:  A - B - C
         /
feature:      D - E

After git rebase master (on feature):
master:  A - B - C
              \
feature:       D' - E'

Use commands:

git checkout feature
git rebase master

# Or rebase interactively (choose, reorder, squash commits):
git rebase -i master
# or -i HEAD~3 (rebase last 3 commits)

When to use:

  • Keep a clean, linear commit history
  • Before pushing to keep remote history tidy
  • Personal branches (not shared with team)
  • Interactive rebase to clean up messy commits

⚠️ Warning: Never rebase public/shared commits (already pushed). Rebase only local commits or risk conflicts for teammates.

Squash Commits

Combine multiple commits into one. Useful before merging a feature to reduce noise.

Scenario:

Before squash:
feature:  add feature - fix typo - adjust styles - update config

After squashing:
feature:  add feature (with all changes)

Method 1: Using rebase -i

git rebase -i master
# In your editor:
#   pick   add feature
#   squash fix typo
#   squash adjust styles
#   squash update config
# Save and edit the new commit message

Method 2: Reset to a commit and re-commit

git reset --soft master
git commit -m "Add feature with all changes"

Method 3: Merge with --squash

git checkout master
git merge --squash feature
git commit -m "Merge feature (squashed)"

When to use:

  • Clean up working branches before PR/merge
  • Hide intermediate "fix typo" or "oops" commits
  • Keep the main branch history concise

Quick Comparison

Operation History Best For Risk
Merge Creates merge commit Team collaboration Cluttered history
Rebase Linear, clean Personal branches Breaks shared history
Squash One commit Feature PRs Loses intermediate info
